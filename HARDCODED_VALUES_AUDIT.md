# RTX5 Broker Admin UI: Hardcoded Values Audit

**Project:** `D:\RTX\rtx5-broker-admin-ui` (React 19 + Vite + Electron)
**Date:** 2026-09-24
**Type:** Read-only audit. No project code was changed.
**Goal:** List everything that is hardcoded in the admin UI, so that every piece of data, setting, list, limit, brand element and feature switch can come from the backend, runtime config or database settings.

---

## How this audit was done

- About 47,000 lines of non-test source were split into **10 areas**. Each area was read **line by line** by a separate auditor, and test files were skipped.
- **What counts as "hardcoded":**
  - URLs, IPs and ports
  - credentials and tokens
  - broker identities
  - mock or fake data
  - fixed option lists that are really business data
  - default values that encode business policy
  - validation limits
  - polling intervals and timeouts
  - role and permission checks
  - locale, currency and timezone assumptions
  - fallbacks that hide missing backend data
  - branding
  - theme colours
- **Balance:** each section also lists what is **already dynamic**, and marks acceptable constants (HTTP status codes, UI debounce, layout math) as **OK** rather than inflating the count.
- **Secrets** are masked in this document (first 4 characters + `***`).
- **The most serious claims were checked by hand:**
  - the committed GitHub token
  - the feed tokens in `wsAuth.js`
  - the Dockerfile `HOST` change
  - the light/dark theme tokens
  - that `brokers.json` is tracked in git

### Severity scale
| Severity | Meaning |
|---|---|
| **Critical** | A secret or credential in the source, fake data shown to users as if it were real, or hidden hardcoded values written to the backend |
| **High** | A business list, policy, broker identity or infrastructure value that must come from the backend; or a fallback that makes up data |
| **Medium** | Config that should be dynamic (limits, defaults, timezone and currency, error states that look like "no data", fixed columns and tabs) |
| **Low** | Tunables, cosmetics, placeholders, i18n, theme colours |

### The 10 most important findings
1. **🔴 Secrets are committed to the repository. Rotate them now.**
   - `.env.electron:3` contains a GitHub token (`ghp_***`). The file is tracked in git despite `.gitignore` *(verified with `git ls-files`)*.
   - `src/utils/wsAuth.js:78-82` hardcodes per-broker feed tokens (`nexa: 'cf9a***'`, `test: '28c2***'`), and they take priority over the user's login token *(verified)*.
   - `ServerPropertiesPopup.jsx:49` has a password literal.
   - `brokers.json` is tracked in git: server IPs, SSH user `root`, SSH port 40111.
2. **🔴 Screens that are fully fake but look live**, with no API calls at all:
   - `ServerStatusPanel`, `NetworkCluster` (real-looking public IPs), `AllocationsView` and `IntegrationsView`
   - the `Time` view in `AdminDataTable`
   - `SupportCenterView` and `AntiDDoSView`
   - the "Settings" tabs in the Server, Manager and Account Allocation popups

   Their charts are generated by `lib/deterministicChart.js`, so they look like real telemetry.
3. **🔴 Hidden hardcoded values are written to the backend:**
   - `CreateGroupPopup` sends `maxLotPerTrade: 100` and `maxTotalLots: 500`, with no input for them.
   - `GroupPropertiesPopup` fills missing fields (leverage 100, lot caps, margin call 100 / stop-out 50, currency USD) and writes the **whole form back on every save**.
   - Several create forms are prefilled with demo data (Christmas holiday, EURUSD 1:500, `std_ecn`, `192.168.1.0/24`).
4. **One broker's identity is built into the core logic:**
   - A complete Nexa broker record is added to **every** broker-discovery result (`brokerAuth.js:518-520`).
   - GTA and FXTrust IPs and domains are matched by text in `backendTarget.js`.
   - The fallback broker is `'Nexa'`.
   - The Super Admin host has 3 different values across files, including a typo (`fxtrustsuperbackned`).
5. **Navigation and permissions are fixed in code.**
   - The sidebar, menu bar, toolbar and context menus are static.
   - `viewCapabilities.js` (45 views) and `permissions.js` (a map of 60+ views to permissions) keep access policy in the frontend.
   - Permissions are keyed by display label, and unmapped views default to allowed. `'Server Configuration'` vs `'Server Config'` bypasses the SERVER_ADMIN check.
6. **Business lists live in the frontend:**
   - account, book and commission types; execution and routing modes; leverage profiles
   - currencies; payment method types; transaction, deposit, withdrawal and chargeback statuses
   - risk limit types and actions; severities; compliance regimes (EU only)
   - complaint categories; feed providers; notification channels; custom-field types
   - market categories (copied **4 times**, each with its own ticker-guessing logic)
7. **Fallbacks invent data instead of showing "unknown":**
   - `leverage || 100`, `status || 'active'`, `'Main Trade Server'`, `'SRV-001'`, `'Connected to RTX5-PROD-01'`, manager login `'10001'`
   - Gateway `{state:'ready'}`, `contract_size ?? 100000`, `digits ?? 5`
   - A missing row ID falls back to the row's position in the list, and that number is used in **delete, resolve and toggle** calls.
8. **Errors look like empty data.** About 20 views use `catch { setData([]) }`. The most dangerous: **Risk Events → "No events found"** and **Suspicious Activity → "No suspicious activity found"** when the backend fails.
9. **Currency, timezone and locale are assumed:**
   - `USD` is hardcoded 36 times; `$` is hardcoded in the deposit-approval confirmation.
   - Prices use `toFixed(5)` instead of the symbol's `digits`.
   - All times use the admin PC's timezone, and date defaults are computed in UTC.
   - Only the first 100 orders and deals ever load (`limit=100&offset=0` is fixed).
10. **There's no branding or theme mechanism.**
    - "RTX5" and "Orrnn", the logo, `support@orrnn.com` and the version fallback are literals.
    - The light theme uses the dark palette, so in the **default** 'light' mode the logo is rendered black on a dark bar.
    - 1,673 raw hex colour classes bypass the tokens.

### Deployment issues found along the way (not hardcoding, but urgent)
- **Uncommitted `Dockerfile` change: `HOST=127.0.0.1`** (was `0.0.0.0`) *(verified with `git diff`)*. The container becomes unreachable through `-p 8080:80`, while the internal health check still passes.
- **`public/runtime-config.js` is committed with the prod `SUPER_ADMIN_API_HOST`** and overrides `.env` in every non-Docker build, including Electron.
- **`docker-entrypoint.sh` leaves out `FEED_WS_URL`, `FEED_STATUS_URL`, `FEED_BROKER_ID`, `DIRECT_MANAGER_ORIGINS` and `FIX_RELAY_ENABLED`**, so per-broker values in `brokers.json` are dropped.
- **`brokers.json`'s GTA entry points at the FXTrust test backend** (looks like a copy-paste mistake).

## Suggested order of work

1. **Now (security):**
   - Rotate the GitHub token and the feed tokens, and remove them from git history.
   - Remove `brokers.json` from git.
   - Revert the `Dockerfile` `HOST` change.
   - Remove the password literal in `ServerPropertiesPopup`.
2. **Stop saving invented values:**
   - Remove the hidden defaults in `CreateGroupPopup` and `GroupPropertiesPopup`.
   - Remove the demo data prefilled in create forms.
   - Stop using a row's list position in place of a missing ID in delete, resolve and toggle calls.
3. **Stop showing fake data as real:**
   - Wire the fake screens to APIs, or hide them behind feature flags or clear "Preview" labels.
   - Replace `catch → []` with error states, starting with Risk Events and Suspicious Activity.
4. **Broker-agnostic build:** remove the Nexa, GTA and FXTrust special cases; the discovery and runtime config become the only source.
5. **Capabilities and enums:**
   - Build `/auth/me` capabilities, `/meta/enums` and `/settings/server`.
   - Replace the static permission and view maps and the business option lists.
6. **Branding and theme:** build `/branding`, create a real light theme, and remove `legacy-overrides.css` by changing the hex classes to token classes.
7. **Polish:** move tunables and timeouts into runtime config, add i18n, add user preferences.

## 1. Infrastructure, Build & Config

**Scope:** .env*, brokers.json, Dockerfile, docker-entrypoint.sh, nginx.conf, server.js, vite.config.js, index.html, public/runtime-config.js, package.json, CI, electron/*, scripts/*, src/config/*, src/lib/*, src/main.jsx, src/App.jsx

### Summary
- **Counts: Critical 1, High 13, Medium 26, Low 52** (items marked OK are not counted).
- **🔴 A secret is committed to git.** `.env.electron:3` contains a GitHub token (`GH_TOKEN=ghp_***`).
  - The file is **tracked in git** even though `.gitignore` lists it. *Verified: `git ls-files` lists it, and it is present in `HEAD`.*
  - Rotate the token now and remove it from the git history.
- **Broker names are hardcoded into the URL logic.**
  - `src/config/backendTarget.js` hardcodes GTA and FXTrust IPs, domains and name substrings, and sends any broker that matches them to fixed URLs.
  - Two of these can't be overridden at all: the FXTrust WebSocket URL and the FXTrust direct-path host check.
  - The test broker is detected by searching `JSON.stringify(env)` for text. Any broker whose settings mention `fxtrust` is treated as the test broker.
- **Deployment config has gaps and conflicts.**
  - `docker-entrypoint.sh` never writes `FEED_WS_URL`, `FEED_STATUS_URL`, `FEED_BROKER_ID`, `DIRECT_MANAGER_ORIGINS`, `FIX_RELAY_ENABLED` or the `*_LEGACY_*` keys to `runtime-config.js`. The frontend reads all of them, so per-broker values in `brokers.json` are silently dropped in Docker.
  - The committed `public/runtime-config.js` pins `SUPER_ADMIN_API_HOST` to prod, which overrides `.env` / `.env.electron` in every non-Docker build, including the desktop app.
  - The Super Admin host has **3 different values** across files: `superadmin-prod`, `superbackend`, and a typo `fxtrustsuperbackned`.
- **Uncommitted change that breaks deployment.** The `Dockerfile` now sets `HOST=127.0.0.1` (*verified with `git diff`*).
  - Node then listens only inside the container, so `-p 8080:80` can't reach the app. The internal health check still passes.
  - The CI deploy also copies the old container's settings (`HOST`, `PORT`, `NODE_ENV`) into the new one, so the bad value would stick even after the Dockerfile is fixed.
- **The broker server list is committed.** `brokers.json` is tracked in git (*verified*). It holds server IPs, the SSH user `root`, SSH port 40111 and internal ports.
  - Its GTA entry points at the FXTrust test backend, which looks like a copy-paste mistake.
- **The desktop build is locked to one broker and one brand.**
  - `.env.electron` builds the Nexa broker into the installer that every broker downloads.
  - `electron/main.js` falls back to a plain-HTTP IP (`http://69.197.178.27`). Packaged builds usually ship without a `.env` file, so that fallback is normally what's used.
  - The name, icon and GitHub owner/repo are hardcoded.
- **Feature switches live in the frontend.**
  - `viewCapabilities.js` hardcodes, for about 45 views, whether each one works, is locked or is static. Views not in the list default to "working".
  - The Super Admin console is always available in every broker deployment.
  - The FIX relay panel can only be switched at build time.
- **Fake chart data:** `lib/deterministicChart.js` is used to generate CPU, connection and memory numbers that look like real metrics.
- **Already dynamic:**
  - The runtime-config → `VITE_*` precedence chain.
  - Docker's runtime injection of config.
  - `server.js` PORT/HOST.
  - Electron origins from env plus IPC, and DevTools gating.
  - Per-broker `direct_manager_paths`.
  - Secrets in CI.
  - `.dockerignore` keeps the env files out of the image.

## 2. Services, Hooks, Store, Utils

**Scope:** src/services/*, src/hooks/*, src/store/*, src/utils/*, src/data/terminalData.jsx

### Summary
- **Counts: Critical 4, High 23, Medium 57, Low 89.** Most Low rows are reasonable tunables, listed so nothing is missed.
- **🔴 Live secrets and one broker's identity are built into the app.**
  - `utils/wsAuth.js:78-82` maps broker IDs to fixed feed tokens (`cf9a***`, `28c2***`). *Verified.* They are added to every feed and metrics WebSocket URL, and they take priority over the user's login token.
  - `wsAuth.js:102` falls back to broker `'Nexa'` when no broker is known, so the Nexa token can be sent to an unknown backend. *Verified.*
  - `services/brokerAuth.js:105-120` hardcodes a complete Nexa broker record (domain, internal IP `100.119.182.26`, WebSocket URLs). Lines 518-520 add it to **every** broker-discovery result.
- **Hardcoded infrastructure and broker-specific logic:**
  - Discovery host fallback `superbackend.orrnn.com`; Super Admin fallback `fxtrustsuperbackned.orrnn.com` (typo).
  - GTA is detected by IP and domain and forced onto login server `broker-server-2`.
  - The test broker falls back to IP `100.120.168.28`.
  - The rule "port 8091 means plain HTTP" appears in about 6 places.
  - A mock list of 4 brokers with real hosts ships in the production bundle.
- **Places that show fake data:**
  - `utils/dummyGroups.js` + `store/useDummyGroupsStore.js` hold a full sample dataset (only shown in the opt-in "Dummy" mode, but it ships in production).
  - `terminalData.jsx` has unused mock tables with a real company name (`Flexy Markets Limited`) and fake managers.
  - The sidebar server cluster is fixed, with fixed health colours ("TradeProcessor SQL_E" is always red).
  - `useExposure` and `useTopAccounts` always return `[]` even though the API exists.
- **The frontend works out market and instrument data itself instead of reading it from the backend:**
  - The category list is copied in **4 places**, and each copy guesses categories with its own regex or ticker list (about 100 tickers).
  - Symbol descriptions are hardcoded, including specific London stocks.
  - Prices use `toFixed(5)` or a size-based guess instead of the symbol's `digits`.
  - New instruments are prefilled with contract specs, `calcModes`, UTC and USD.
- **Roles and permissions are hardcoded:**
  - `utils/permissions.js` has a fixed permission list and a fixed map of 60+ views to permissions.
  - The roles `admin` and `super_admin` automatically get everything.
  - `sessionUser.js` makes up an id, a role and full permissions when the backend leaves them out.
- **Fallbacks that hide missing backend data:**
  - `leverage || 100`, `type || 'Individual'`, `status || 'Active'`.
  - A missing `enabled` flag counts as true.
  - `role:'super_admin'` is set when the login response has no user.
  - `.catch(() => [])` turns a failed request into an empty list.
  - The rule `volume >= 100 → /10000` guesses the volume unit.
- **Hardcoded business limits:** a money cap of 1e9 with 2-decimal rounding (wrong for JPY and crypto), password length 12–72, leverage 1–10000, depth levels 1–50, `max_volume` 999999, and symbol names of at most 20 characters.
- **Hardcoded timing and paging:**
  - Positions poll every 2 s and the feed status every 15 s.
  - The feed reconnects after 500 ms with no backoff.
  - Quotes count as fresh for 30 s.
  - Various timeouts and cache lifetimes.
  - `BrokerOrders/BrokerDeals?limit=100&offset=0` is fixed, so **only the first 100 orders and deals ever load**.
- **Already dynamic:**
  - API hosts come from runtime config or Vite env, and WebSocket URLs are built in `config/endpoints.js`.
  - The broker list comes from `/api/v2/broker/servers`.
  - The market-watch symbol list comes from the feed status endpoint.
  - LP mappings, feed tenants, gateway, role defaults, holidays, leverage and servers all come from APIs.
  - `groupTreeData` loads every page.
  - `services/authService.js` appears unused.

**Scope:** AuthenticatedApp.jsx, MenuBar, ActionToolBar, TabBar, SidebarNavTree, TreeItem, AboutModal, HelpModal, AdminContextMenu, BrokerAuthScreens, SuperAdminAuthScreen, ErrorBoundary, atoms/*, ui/*, index.html

### Summary
- **Counts: Critical 0, High 11, Medium 28, Low 40 (79 findings).** No secrets, passwords, demo credentials, OTP lengths or lockout rules are hardcoded in this area.
- **Navigation is fully static (High).**
  - The sidebar tree is the static `sidebarData` in `src/data/terminalData.jsx` (453 lines).
  - `LOCKED_DROPDOWN_LABELS` hardcodes 7 locked modules.
  - The MenuBar menus, all 9 ActionToolBar groups and the 14-item AdminContextMenu are JSX literals.
  - None of them filter by the user's permissions; users only find out after clicking (`AccessDeniedPanel`).
- **Permission checks rely on display labels and allow by default (High).**
  - `VIEW_PERMISSIONS` is keyed by label, and `hasPermission(user, null)` returns true.
  - The toolbar's `'Server Configuration'` doesn't match the permission key `'Server Config'`, so the SERVER_ADMIN check never applies to it.
  - 7 Window-menu labels have no permission mapping.
  - `canAdd`/`canImport` are granted by view name.
- **Made-up or placeholder runtime data:**
  - The status bar always says `Connected to RTX5-PROD-01`.
  - Server popups get a random ID (`Math.random()*10+1`).
  - The toolbar says "Connected to RTX5 Trade Server".
  - The group name is prefilled as `'New Group\\Demo'`.
  - The Notifications menu is static text.
  - "Remember me" and "Forgot password?" on the broker login do nothing.
- **Branding is hardcoded and inconsistent.**
  - Fixed values: support email `support@orrnn.com`, vendor `Orrnn`, version fallback `1.0.0`, and the logo, hero image and favicon.
  - The product name is spelled 5 ways (`RTX 5 Admin`, `RTX5 Admin`, `RTX5 Broker Admin`, `RTX 5 Admin Terminal`, `RTX5 Technology Admin`).
  - None of it uses the existing `public/runtime-config.js` hook.
- **Auth screens: mostly dynamic.**
  - The broker list comes from the API, the broker lock from runtime config, and logos from `logo_url`. No default credentials.
  - Problems: the Super Admin screen prefills the username `admin` and shows the login API path.
  - Every broker login page links to the "Super Admin Portal".
- **Magic numbers:**
  - Auto-refresh is 15 s, and that number is repeated in 2 text strings.
  - Other intervals: session poll 2 s, release check 10 min, auto-theme switch at 06:00/18:00.
  - The clock shows the client's local time, not server time.
- **Theme bypass:**
  - Both auth screens use about 20 literal hex colours instead of theme tokens.
  - The TreeItem active row is `#04395e`/`text-white`, which is poor in the light theme.
  - The `ui/*` primitives do use theme tokens throughout.
- **Already dynamic:**
  - Permissions (`getMe` → `canAccessView`/`hasPermission`), token expiry, and connection status (`connectionStore`).
  - The desktop version check (GitHub latest-release API plus Electron IPC).
  - The Super Admin backend origin, and the admin name, login and broker ID.
  - `TerminalIcon` can already render icons by name, which a backend-driven menu would need.
- **i18n:** every user-facing string is an inline English literal. There is no i18n layer.

**Scope:** SymbolManagement/*, SymbolVisibilityView, SymbolCatalogueCells, GroupsExplorer, GroupsNavigation, DummyGroups*, SwapFreeGroupsView, LeveragesView, LeverageScheduleView, SpreadsView, SessionOverridesView, HolidaysView

### Summary
- **Counts: Critical 0, High 7, Medium 43, Low 64 (114 rows).**
- **No mock data on any screen users can reach.** Symbols, categories, sessions, holidays, spreads, leverage tiers and LP mappings all come from `InstrumentsService`, `ManagerService`, `PlatformConfigService`, `services/api` and the live `useSymbolStore`.
- **The only mock data isn't rendered.** `DummyGroupsExplorer.jsx` and `DummyGroupsNavigation.jsx` are not imported anywhere.
  - Their seed in `utils/dummyGroups.js` is labelled "(Dummy)".
  - Leftover wiring remains in `AuthenticatedApp.jsx` (`isDummy`, `dummyActionsRef` at L103, 513-514, 760-761, 1000).
  - `docs/groups-dummy-workspace.md` describes a "Dummy data" selector that no longer exists.

- **Business option lists are hardcoded in the browser:**
  - commission types `per_lot/percent/per_deal` and swap-free modes `full/partial`

  - The clone form uses contract size 100000 and 0.01–100 lots for any source symbol.

  - Market depth defaults to 10 levels and 100 ms.
- **Fallbacks hide missing or failed backend data:**
  - A missing `enabled`/`visible` flag is shown as true.
  - **A missing row ID falls back to the row's position in the list, and that number is then used in delete calls.**

- **Timezones are assumed.** Leverage-schedule dates are sent with no timezone. Session, spread and override times show no timezone. `symbol_timezone` is free text defaulting to `'UTC'`.
- **Two bugs found:**
  - `LeveragesView` L50 passes a rule ID into `getLeverageScheduleList(group)`.
  - `SessionsTab` uses `<input type="time">`, which can't hold `24:00`.
- **Already dynamic:**
  - Every Symbol Management tab loads and saves through backend CRUD.

## 8. Payments, Risk, Analytics, Compliance

**Scope:** PaymentGateway/Methods/Reconciliation/Payments, Deposits, Withdrawals, Chargebacks, TransactionHistory, Analytics*, RiskEvents/Limits/Reports, RegulatoryReports, SuspiciousActivity, Complaints, DataExports

### Summary
- **Counts: Critical 0, High 10, Medium 52, Low 50 (112 findings).**
- **No fake data on any screen users can reach.** 18 of the 20 views get all their rows and KPIs from `PaymentService`, `AnalyticsService`, `RiskManagementService` or `ReportsService`.
- **The only mock data is in dead code.**
  - `PaymentsView.jsx` hardcodes 6 real payment providers (Ecommpay, APS, Bitronum/EUPaymentz, Unlimit, Kora, emerchantpay), with named contacts' emails and phone numbers and made-up stats. Nothing imports it, and a test checks that it stays that way. **Delete it or connect it to an API.**
  - `AnalyticsExportsView.jsx` is also unused.
- **Main issue: business option lists are hardcoded (about 25 findings):**
  - payment method types; deposit, withdrawal and chargeback statuses; transaction types
  - risk limit types and actions; risk severities; suspicious-activity pattern types and review actions
  - complaint categories, priorities and statuses
  - export report types and formats; regulatory regimes (EMIR/MiFID/AML only)
- **Errors look like "nothing found" in 7 places.** The worst:
  - Risk Events shows "No events found" and Suspicious Activity shows "No suspicious activity found" **when the backend fails**, so operators see no alerts.
  - Risk Reports shows "No toxic flow detected" before anything has loaded.
- **Currency and locale are assumed.**
  - Deposit and withdrawal forms default to `'USD'` in a free-text field.
  - **The deposit approval confirmation hardcodes `$`** whatever the deposit's currency is (High).
  - Regulatory tables apply `toFixed(4)` to every number, so a login shows as `12345.0000`.
- **Timezones are assumed.**
  - Every table shows times in the admin's own PC timezone (`toLocaleString`).
  - Default dates are computed in UTC, so "yesterday" can be off by one day.
  - Risk Reports treats the "to" date as UTC midnight, which leaves out the last day.
- **Missing IDs can change the wrong record.** When a row has no ID, its position in the list is sent to toggle a gateway, match a reconciliation record or resolve a chargeback.
- **Edit forms fill missing fields with defaults** (`'max_drawdown'`, `'alert'`, `enabled ?? true`, `'finance'`, `'medium'`), and saving writes those invented values to the backend.
- **Hardcoded thresholds:** toxic-flow win-rate colour bands (80% / 70%), a 30-day default report window, and a transaction limit of 200 written 3 times.
- **Already dynamic:**
  - All list data, gateway health, reconciliation, analytics tables (columns come from the response) and trader rankings.
  - Broker PnL, toxic flow, EMIR/MiFID/best execution, KYC, suspicious-activity stats and chargebacks.
  - Analytics views use `useCachedTabRequest` with proper error states, and RiskLimitsView uses `buildActionableErrorState`.

## 10. Theme, CSS & Project-wide Search

**Scope:** src/**/*.css, src/theme/*, plus project-wide searches over all .jsx files

### Summary
- **Scope:** all 13 `src/**/*.css` files (3,392 lines), plus a search across the 116 non-test `.jsx` files. There is no `tailwind.config.*`: Tailwind v4 is configured CSS-first (`@theme` in `src/index.css`).
- **The token layer exists and is mostly used correctly.**
  - `tokens.css` defines about 50 CSS variables.
  - `index.css @theme` points Tailwind's `green/emerald/lime/red/rose-*` at the semantic tokens.
  - JSX uses `var(--…)` 3,401 times across 107 files.
- **The tokens are fixed at build time.** Nothing loads them at runtime, and **no branding mechanism exists anywhere**: product name, logo, vendor and support email are all literals.
- **🔴 The light theme doesn't exist.** *Verified.*
  - `tokens.css:5-7` gives `:root`, `[data-theme="light"]` and `[data-theme="dark"]` the same dark values.
  - Yet the app **defaults to `'light'`** (`AuthenticatedApp.jsx:122`) and offers a light/dark/system/auto switch.
  - In the default mode, `MenuBar.css:36` makes the brand logo black (`brightness(0)`) on the dark #181818 bar.
  - Also in the default mode, `legacy-overrides.css:145` forces light-style native inputs onto the dark UI.
- **Raw hex colours bypass the tokens on a large scale.**
  - JSX uses **1,673 Tailwind hex colour classes** (209 distinct, in 61 files).
  - `legacy-overrides.css` (405 lines) re-maps 113 of them to tokens with `!important`. **96 classes (294 uses) are not re-mapped at all.**
  - A further 107 hex strings sit in JS, inline styles and SVGs.
- **Some screens have their own palettes outside the token system:**
  - `SuperAdminConsole.jsx`: 245 slate/blue/indigo classes, plus `#0b0f17` and `#121824`.
  - `BrokerAuthScreens.jsx`: a hardcoded light palette.
  - Elsewhere: 524 Tailwind palette classes with no token alias, and 1,180 `text-white`/`bg-black` literals.
- **Component CSS still has literals:**
  - `MarketWatchDock.css:8-19` defines a private copy of the palette (12 hex values), so theme changes don't reach the dock.
  - `DummyGroupsExplorer.css` hardcodes its own blue button gradient.
  - Fallback colours (`var(--x, #fallback)`) use an older palette.
  - `manager-ui.css` redefines `--accent-soft` with a different blue from `--accent-500`.
- **Fonts and sizes:**
  - JSX has 3,670 hardcoded pixel classes such as `-[11px]`; `typography.css` maps most of them onto the size tokens.
  - Manrope is bundled but never used, and JetBrains Mono is referenced but not bundled.
- **Locale and currency:**
  - No `'en-US'` literals; the app uses the browser's locale.
  - **`USD` is hardcoded 36 times in JSX.**
  - `$` is used as a prefix in `GroupPropertiesPopup` and `DepositsView`.
- **Brand strings:** "RTX" appears on 42 lines in 18 files and "Orrnn" 8 times. There is no "©" anywhere.
