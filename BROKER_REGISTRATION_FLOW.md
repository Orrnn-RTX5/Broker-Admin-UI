# Broker Registration Flow - Implementation Guide

## Overview
This document describes the new broker registration flow implemented in the RTX 5 Admin Terminal. The flow allows broker administrators to register new brokers and login with credentials provided by SuperAdmin.

## Architecture Flow

### Complete Broker Registration Process

```
┌─────────────────────────────────────────────────────────────────┐
│  STEP 1: Broker Selector (Initial Screen)                       │
│                                                                  │
│  Two Options:                                                   │
│  ┌──────────────────────┐    ┌──────────────────────────────┐  │
│  │ Select from List     │    │ Register New Broker (Manual) │  │
│  │ (Dropdown)           │    │ (Direct Credential Entry)    │  │
│  │                      │    │                              │  │
│  │ Uses existing brokers│    │ For first-time brokers not   │  │
│  │ from discovery API   │    │ yet in the system            │  │
│  └──────────────────────┘    └──────────────────────────────┘  │
│            │                           │                        │
│            ▼                           ▼                        │
│      ┌──────────────┐        ┌──────────────────┐              │
│      │ Manager Login│        │Manual Broker Entry│              │
│      │ or Admin     │        │ Screen           │              │
│      └──────────────┘        └──────────────────┘              │
└─────────────────────────────────────────────────────────────────┘
```

## Screen Flow

### 1. Broker Selector Screen (`/`)
**Initial authentication screen showing two options:**

#### Option A: Select from List (Default)
- Fetches active brokers from discovery API
- Shows broker list in dropdown
- User selects broker → continues to Manager Login or Admin Login
- Endpoint: `GET {DISCOVERY_BASE_URL}/api/v1/broker/servers`

#### Option B: Register New Broker (+Register new broker button)
- Navigates to Manual Broker Entry screen
- For brokers not yet registered in discovery service
- Uses manually provided credentials

---

### 2. Manual Broker Entry Screen (`/broker-manual-entry`)
**Two-step form for broker registration:**

#### Step 1: Credential Entry
User provides:
```
┌─────────────────────────────────────────┐
│ Manual Broker Registration              │
├─────────────────────────────────────────┤
│ Broker ID *                             │
│ [e.g., my_broker]                       │
│                                         │
│ License Key (Optional)                  │
│ [RTX5-ENT-MYBRO-2026-A1B2C3D4...]       │
│                                         │
│ Manager Login # *                       │
│ [e.g., 10016]                           │
│                                         │
│ Password *                              │
│ [Broker@A3F9D2E1B8C4F7E2...]            │
│                                         │
│ Server URL/IP *                         │
│ [e.g., 103.91.186.142:8091]             │
│ [or: https://broker.example.com]        │
│                                         │
│ [Validate & Continue] [← Back]          │
└─────────────────────────────────────────┘
```

**Field Details:**
- **Broker ID**: Unique identifier for broker (matches SuperAdmin broker_id)
- **License Key**: Optional, for audit trail (from SuperAdmin create response)
- **Manager Login #**: Numeric manager account ID (auto-generated by SuperAdmin)
- **Password**: Manager account password (auto-generated by SuperAdmin)
- **Server URL/IP**: Broker VPS endpoint
  - Format: `103.91.186.142:8091` or `https://broker.example.com`
  - Supports IP+port, domain, or full URL
  - Port 8091 uses HTTPS, others use HTTP (configurable)

**Validation Process:**
```javascript
validateBrokerCredentials({
  broker_id: 'my_broker',
  license_key: 'RTX5-ENT-MYBRO-2026-...',
  server: '103.91.186.142:8091'
})
```

- Normalizes server URL
- Creates broker info object
- Validates format and accessibility
- Throws error if invalid

#### Step 2: Confirmation
Shows confirmed broker details:
```
┌─────────────────────────────────────────┐
│ Confirm Broker Registration             │
├─────────────────────────────────────────┤
│ Broker ID:      my_broker               │
│ Manager Login:  10016                   │
│ Server:         https://103.91.186.142  │
│                                         │
│ [Sign In] [← Back to entry]             │
└─────────────────────────────────────────┘
```

Logs in with provided credentials using the standard manager login flow.

### 3. Login Screens
#### ManagerLogin (`/manager-login`)
After broker selection, manager staff logs in:
```javascript
POST {BROKER_URL}/manager/api/v2/auth/login
{
  "user": "10016",           // Manager login number (string)
  "password": "Broker@...",  // Manager password
  "server": "my_broker"      // Broker ID
}
```

**Response:**
```javascript
{
  "token": "2df7c23f-62e9-...",
  "refresh_token": "848a6a12-0480-...",
  "login": 10016,
  "is_admin": false,
  "broker_id": "my_broker"
}
```

#### AdminLogin (`/admin-login`)
For admin-only operations:
```javascript
POST {BROKER_URL}/manager/api/v2/admin/login
{
  "user": "10016",
  "password": "Broker@..."
}
```

## Service Implementation

### brokerAuth.js - New Functions

#### validateBrokerCredentials(options)
```javascript
export const validateBrokerCredentials = async ({ 
  broker_id,      // Broker identifier
  license_key,    // Optional license key
  server          // Server URL/IP
}) => {
  // Returns normalized broker info:
  // {
  //   broker_id: 'my_broker',
  //   name: 'my_broker',
  //   status: 'active',
  //   backend_url: 'https://103.91.186.142:8091',
  //   server_ip: '103.91.186.142',
  //   license_key: '...'
  // }
}
```

#### normalizeBackendUrl(server)
Converts various URL formats to standard backend URL:
- `103.91.186.142:8091` → `https://103.91.186.142:8091`
- `broker.example.com` → `https://broker.example.com`
- `http://broker.example.com:8000` → `http://broker.example.com:8000`
- `broker.example.com:8000` → `http://broker.example.com:8000`

**Rules:**
- Port 8091 uses HTTPS by default
- Other ports use HTTP by default
- Full URLs (http/https) passed through as-is

## Component: ManualBrokerEntry

**File:** `src/components/organisms/BrokerAuthScreens.jsx`

**Props:**
```javascript
{
  navigate: (path, options) => void,  // Route navigation
  onLoginSuccess: (session, path) => void  // Auth success callback
}
```

**State:**
- `brokerId`: Broker ID input
- `licenseKey`: License key input
- `user`: Manager login number input
- `password`: Manager password input
- `server`: Server URL/IP input
- `error`: Error message
- `loading`: Loading state
- `step`: 'credentials' | 'confirm'

**Flow:**
1. User enters credentials in Step 1
2. Form validates on submit
3. Calls `validateBrokerCredentials()` on validation
4. Moves to Step 2 (confirmation)
5. On final submit, calls `loginManager()` with credentials
6. Sets auth session and redirects to dashboard

## Integration with SuperAdmin Flow

### SuperAdmin Creates Broker
```javascript
POST /api/v1/brokers
{
  "broker_id": "my_broker",
  "name": "My Broker Ltd",
  "server_ip": "103.91.186.142",
  "api_url": "https://103.91.186.142:8091"
}

// Response includes:
{
  "license_key": "RTX5-ENT-MYBRO-2026-A1B2C3D4E5F6",
  "manager_credentials": {
    "login": 10016,
    "password": "Broker@A3F9D2E1B8C4F7E2...",
    "name": "My Broker Ltd Admin"
  }
}
```

### Broker Admin Registers in Frontend
1. Opens RTX 5 Admin Terminal
2. Clicks "+ Register new broker"
3. Enters:
   - `Broker ID`: my_broker
   - `Manager Login #`: 10016
   - `Password`: Broker@A3F9D2E1B8C4F7E2...
   - `Server`: 103.91.186.142:8091
4. System validates and confirms
5. Proceeds to login

## Error Handling

### Common Validation Errors
```
❌ "All fields are required"
   → User left required fields empty

❌ "Invalid broker server URL or connection failed"
   → Server URL format invalid or server unreachable

❌ "Server URL is required"
   → Server field empty

❌ "Invalid server URL format"
   → URL doesn't match expected patterns
```

### Login Errors
```
❌ "Wrong login or password"
   → Invalid manager credentials

❌ "Account is disabled"
   → Manager account disabled on broker

❌ "Server mismatch - please switch broker"
   → Broker ID mismatch with server
```
